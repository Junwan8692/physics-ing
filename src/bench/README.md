# 솔버 벤치

```bash
npm run bench      # = vitest run src/bench --reporter=verbose
```

`solver.bench.test.ts`가 (크롭 크기 3 × 칠한 면적 3 × 품질 티어 3) = 27개 조합에서
`PhysicsSimulator.step()` 비용을 600스텝 평균으로 재고 표로 찍는다.
메시는 `gridForImage`(짧은 변 25칸, 스펙 §4.1)로 만들고, 마스크는 크롭 면적의 정확히
2% / 10% / 30%를 덮는 중심 원이다. 프리셋은 `purupuru`, 시드 1.

## 표 읽는 법

| 열 | 뜻 |
|---|---|
| `verts` | 메시 전체 정점 수 |
| `dyn` | 칠한(=움직이는) 정점 수. **비용은 여기 붙지 `verts`에 붙지 않는다** (핀 정점 36.2ns vs dynamic 2.4~3.6µs, 스펙 §4.2) |
| `us/step` | `step()` 1회 평균 µs |
| `ms/frame x2` | 활성 컷 2개 기준 프레임당 물리 시간 |
| `vs budget` | 스펙 §8의 0.8 ms/frame 대비 |
| `inverted` | 측정 끝 시점에 뒤집힌 삼각형이 있었는지 (관측값, 단언 아님) |

**`tickRate`가 60이므로 60fps에서 컷당 프레임당 정확히 1스텝이다.** 그래서
`ms/frame = us/step × 활성컷수 / 1000`. 프레임률이 떨어지면 `advance()`가 최대
`maxCatchUpSteps`회까지 몰아 돌리므로 그 프레임만 그만큼 비싸진다 (절벽 = `mcs / tickRate`,
high 티어 66.7ms — 스펙 §4.3).

## 이 숫자를 그대로 결론으로 쓰지 말 것

- **기계 하나의 숫자다.** 목표치 0.8 ms/frame은 "Apple Silicon 기준, 중급 폰이 단일스레드
  JS에서 5배 느리다"는 스펙 §8의 가정에서 역산한 값이다. 실제 폰에서 재기 전까지는 가정이다.
- **JIT·전력 상태·다른 프로세스에 흔들린다.** 같은 커밋에서 다시 돌려도 10~20%는 움직인다.
  한 번 재고 비교하지 말고, 바꾸기 전후를 같은 세션에서 재라.
- **시간에 대한 단언은 없다.** CI에서 반드시 깨지기 때문이다. 이 파일이 `.test.ts`인 건
  vitest 하네스를 재사용하려는 것뿐이고, 유일한 단언은 발산하지 않았다는 것(`isFinite`)이다.
- **마스크가 합성이다.** 중심 원은 실제 웹툰 마스크(머리카락 같은 가늘고 긴 모양)와 다르다.
  클러스터 수·구속 밀도가 달라지면 비용도 달라진다.
- 티어 간 차이는 `iterations` 4 → 3 하나뿐이므로 관측되는 절감은 스펙 §4.3의 19~20%대다.
  `low`는 `medium`과 스텝 비용이 같고 `maxCatchUpSteps`만 4 → 8이다 (느린 프레임에서
  슬로모션 대신 최악 프레임을 감수하는 선택). **스텝당 비용으로 medium과 low를 구분하려 하지 말 것.**

## 관측 메모 (2026-07-25, Apple Silicon / Node 22)

- 30% 칠한 900×1800 크롭(dyn 370)은 `high`에서 1.09 ms/frame로 **예산을 넘는다.**
  30%는 크롭 면적 대비이므로 이미 상당히 큰 마스크다. 예산 안에 두려면 저작 시점에
  마스크를 줄이거나(=크롭이 작아진다) 활성 상한을 1로 내린다 (스펙 §4.3 하향 사다리 2단).
- 같은 조합에서 `iterations` 3(medium/low)은 뒤집힌 삼각형이 남았다. **품질 하향이
  공짜가 아니라는 신호다.** 큰 마스크에서 하향할 때는 시각 확인이 필요하다.
- 구동 세기를 1.5 → 3.0으로 올리면 640×800/30%도 접힌다. 벤치는 시간 재는 게 목적이라
  1.5를 쓴다. 접힘 한계 자체를 재려면 별도 실험을 만들 것 — 이 파일이 아니다.
